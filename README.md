# 🚫 底层红线规则（The Red Lines）

## 一、 系统调用与底层驱动（严禁 CLI 拾荒）
1. **严禁使用 `subprocess`、`os.system` 或 `os.popen` 去轮询执行外部命令行（如 wpctl, xdotool, grep, awk 等）来获取系统状态。**
2. 凡涉及系统硬件、网络、媒体、窗口管理器交互，**必须**寻找原生 C/Python API 绑定（如 `pulsectl`），或使用原生 **D-Bus IPC** (基于 `dbus-next`) 进行事件监听。
3. 如果确实没有原生接口必须调用外部命令，只能作为一次性动作（如启动某程序），绝不允许放在高频循环或异步 Task 中。

## 二、 并发与事件模型（严禁瞎子轮询）
1. **严禁使用基于 `while True + sleep` 或 `QTimer` 的盲目轮询机制去检测状态变化。**
2. 必须使用**中断/回调/事件驱动（Event-Driven）**模型。系统闲置（如无音乐播放、界面被隐藏）时，后台线程和 EventLoop 必须进入绝对休眠，CPU 占用率必须逼近 **0.00%**。
3. 前后端通信必须遵循**单向数据流**，通过统一的 Signal/Slot 桥接，严禁跨模块直接强行干预（私开后门发信号）。

## 三、 Qt/QML 前端渲染（严禁状态失禁与死循环）
1. **严禁使用 `Timer`（如 debounce timer, grace timer）来控制 UI 的核心状态流转或掩盖物理穿模 Bug。**
2. UI 交互与动画必须使用 QML 标准的声明式状态机（`states` + `transitions`）或物理协调器统一接管。
3. **严禁在 QML 内部产生属性脏检查风暴（Property Binding Loops）。** 任何会高频变化的数值（如音频波形、秒数跳动），其动画必须交由 GPU (`transform: Scale/Translate`) 处理，**绝对禁止**高频打断或改变父容器的 `width/height` 等几何属性。

## 四、 状态与内存管理（绝对单一事实源 SSOT）
1. 全局状态只允许在 `backend.state` 中存一份，严禁在 Bridge 或视图层私自 `_cached_xxx` 建立影子变量。
2. 捕获异常必须有精准的类型和清晰的 Log，**严禁使用静默的 `try...except: pass` 吞噬致命错误**。
3. 对于频繁创建的 QML 对象或 Python 数据结构，必须考虑垃圾回收（GC），严禁造成内存泄漏。
